# 06 – Incident Investigation

## Objective

Conduct a security investigation based on the alert generated in the previous section, which detected repeated attempts to access blocked websites.

The objective is to examine the related proxy logs, analyze the user's activity, establish an event timeline, and document the investigation findings.

## Investigation Scenario

The investigation focuses on repeated blocked access attempts detected by Splunk.

- **User:** Ahmed
- **Destination:** TradingView
- **Blocked Attempts:** 12
- **Detection Window:** 5 minutes
- **Proxy Action:** TCP_DENIED/403
- **Alert:** Excessive Blocked Web Access Attempts

## Investigation Process

### 1. Alert Review

Review the alert generated by Splunk to identify the activity that triggered the detection and establish the scope of the investigation.

### 2. Event Analysis

Analyze the related Squid access logs to examine:

- Username associated with the activity.
- Targeted website and destination.
- Number of blocked requests.
- Proxy access decisions.
- Event timestamps.

### 3. Timeline Analysis

Build a timeline of the detected activity to understand when the repeated attempts occurred and how they developed over time.

### 4. Investigation Findings

Evaluate the collected evidence to determine whether the activity was successfully blocked and whether additional investigation is required.

### 5. Incident Investigation Report

Document the investigation process, supporting evidence, timeline, findings, and recommended actions.

## Outcome

The investigation documents the repeated blocked access activity detected by Splunk and provides an evidence-based assessment of the proxy events.

The findings and recommendations will support further security review and incident handling.
